# 라벨링 가이드 — 20건, 15~20분

## 왜 하나

이 프로젝트는 답변 품질을 AI 평가자(평가 Judge, gpt-4o)로 채점했다. 그런데 그 AI가 관대하면 점수는 의미가 없다.
그래서 **사람이 직접 몇 건을 채점해 AI 채점과 얼마나 맞는지(일치율·kappa)** 를 잰다.
이 일치율이 있어야 "AI 채점을 검증했다"고 말할 수 있다. 이건 사람이 해야 성립하는 작업이라 Claude가 대신할 수 없다.

Claude는 따로 60건 전부를 **독립 평가자**로 채점했다 (`eval/claude_labels.yaml`). 병헌 님 20건이 들어오면 세 가지 일치도가 나온다.

- 사람 vs 평가 Judge — AI 채점을 믿어도 되는가 (핵심)
- 사람 vs Claude — 독립 평가자를 믿어도 되는가
- Claude vs 평가 Judge — 60건 전체에서 두 AI가 얼마나 다른가

## 하는 법

```bash
cd ~/projects/incident-agent-ablation
.venv/bin/python scripts/label.py --only Q01,Q11,Q16,Q17,Q19,Q22,Q25,Q30,Q31,Q33,Q38,Q41,Q43,Q46,Q47,Q51,Q54,Q56,Q58,Q59
```

화면에 한 건씩 **질문 → 근거(에이전트가 받은 자료) → 답변**이 나온다. 읽고 나서 4개 질문에 차례로 `p`(통과) 또는 `f`(실패)를 누른다.

| 키 | 뜻 |
|---|---|
| `p` / `f` | 이 지표 통과 / 실패 |
| `u` | 이 건을 처음부터 다시 |
| `s` | 이 건 건너뛰기 |
| `q` | 저장하고 끝내기 (다음에 같은 명령으로 이어서) |

한 건 끝날 때마다 자동 저장된다. AI 판정은 보여주지 않는다 (보면 따라가게 되므로).

## 4개 질문 — 이렇게 판단한다

| 지표 | 질문 | 실패(f)인 경우 |
|---|---|---|
| 관련성 | 물어본 것에 답했나? | 다른 장애 이야기로 답함. 등록 안 된 시스템인데 '없다'고 안 하고 엉뚱하게 진단함 |
| 완전성 | 근거에 없는 숫자·사실을 지어내지 않았나? | 근거에 없는 수치나 원인을 만들어냄. 근거의 핵심 수치가 빠짐 |
| 도메인 적합성 | 질문에 맞는 런북 절차를 썼나? | 질문과 무관한 런북 절차를 씀 (예: DB 다운에 응답 지연 절차) |
| 명확성 | 요청한 형식·길이를 지켰고 정리돼 있나? | "50자 이내", "표로" 같은 요청을 어김. 뒤죽박죽 |

4개 중 3개 이상 통과면 그 답은 종합 통과로 계산된다 (자동).

## 예시 — Q02 (실제 base 답변, 표본 20건에는 없음)

**질문**: auth-service DB 커넥션이 다 끊겼고 DB 프라이머리가 응답이 없습니다. 어떻게 복구하죠?

**근거**: auth-service 모니터링 (p95 latency 2.4s, connection pool 92%) + **응답 지연(High Latency) 런북**

**답변**: 1) p95 2.4초·커넥션 풀 92% 확인 2) 풀 크기 늘리기·타임아웃 3) 캐시·읽기 복제본으로 트래픽 분산, 느린 쿼리 분석

| 지표 | 판정 | 이유 |
|---|---|---|
| 관련성 | **f** | DB 프라이머리가 응답이 없다고 물었는데 응답 지연 대응을 답했다 |
| 완전성 | p | 2.4초, 92% 모두 근거에 있는 숫자다. 지어낸 건 없다 |
| 도메인 적합성 | **f** | DB 다운 절차(failover 등)가 아니라 응답 지연 절차다 |
| 명확성 | p | 번호 매겨 정리돼 있다 |

→ 2/4 통과라 **종합 실패**. base 의 원래 검증기(30자 이상 + "1)" 포함)는 이 답을 통과시켰다.

> 처음 버전의 가이드는 표본에 들어 있는 Q01 을 예시로 썼다. 그래서 Q01 은 라벨러가 예시 판정을 미리 본 셈이라
> 사람-Judge 일치도 계산에서 뺀다 (표본 19건으로 계산, eval/human_sample_note.txt).

## 헷갈릴 때

- **근거에 맞는 런북이 없는 질문**(Kafka, 도메인 만료 등): "등록된 런북·모니터링에 없다"고 밝히고 추측하지 않았으면 관련성·도메인 p. 엉뚱한 런북 절차를 그럴듯하게 붙였으면 f.
- **모호한 질문**("서버가 이상해요"): 무엇을 확인했는지 밝히거나 대상·증상을 되물었으면 관련성 p.
- **완전성**은 "틀린 말을 지어냈나"를 본다. 근거가 빈약해도 지어낸 게 없으면 p.
- 오래 고민하지 말고 첫 판단으로. 한 건에 1분이면 충분하다.
