### 2. 베이스 코드를 src/ 로

교수님 제공 베이스 AI 에이전트 코드를 `src/` 아래에 넣는다.
넣은 직후 **원본 그대로 한 번 돌려본다.** 여기서 안 돌면 Ablation 전체가 성립하지 않는다.

### 3. src/adapter.py 작성

평가 하네스가 부르는 단일 진입점. 이것만 맞으면 `eval/` 전체가 동작한다.

```python
def run_once(query: str, config: dict) -> dict:
    return {
        "answer":     str,    # 최종 답변
        "context":    str,    # 수집된 근거 (Judge completeness 판정 대상)
        "retrieved":  [str],  # 선택된 런북 id, 순위 순서 (Recall@k 대상)
        "rewrites":   int,
        "tokens":     {"prompt": int, "completion": int},
        "latency_ms": float,
        "trace_url":  str | None,
    }
```

주의할 점 두 가지.

- `retrieved` 는 **base 구성(키워드 규칙)에서도 반드시 채운다.** 키워드가 고른 런북 id를 그대로 넣으면
  RAG 구성과 같은 지표(Recall@k)로 비교할 수 있다. 이게 이 프로젝트의 핵심 차별점이다.
- `context` 는 write 노드에 들어간 근거 원문이어야 한다. 최종 답변을 다시 넣으면
  completeness 판정이 무의미해진다.

## 이 프로젝트가 다른 43명과 갈리는 지점

동기 126명 전수조사 결과 과제1 선택자는 43명이다. 그중

- 검색 품질 지표를 따로 재는 사람: **1명**
- Judge 자체 신뢰도를 검증하는 사람: **3명**
- 캐싱을 하는 사람: **0명**

"RAG 넣고 Judge 넣었다"는 이미 포화다. 갈리는 건 **개선의 원인을 분리해서 증명하는 것**이다.
그래서 `retrieved` 를 base에서도 채우는 것과 `human_label` 을 끝까지 채우는 것,
이 두 가지를 타협하면 이 프로젝트는 평범해진다.
