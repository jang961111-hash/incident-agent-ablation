# 실시간 시연 가이드 (OpenAI, 원본 vs 최종 나란히)

같은 질문을 원본(base)과 최종(final)에 동시에 넣고, 고른 매뉴얼·답·지연·비용을 터미널에 나란히 보여 준다.
질문 1개당 약 15초, 비용 1센트 미만(리허설 실측: 원본 $0.0028~0.0029, 최종 $0.0004~0.0005).

## 준비 (시연 전 1분)

1. iTerm2(터미널)를 **화면 가로 전체로 넓힌다**. 좌우 두 칸이 나란히 나오려면 약 160칸 폭이 필요하다.
2. 글자가 작으면 `Cmd+-` 로 줄이고, Zoom 에서는 **터미널 창만** 공유한다.
3. 프로젝트 폴더로 이동한다.

```bash
cd ~/projects/incident-agent-ablation
```

## 시연 1: DB 다운 (핵심, 꼭 보여 줄 것)

```bash
LANGCHAIN_TRACING_V2=false .venv/bin/python scripts/demo_side_by_side.py "DB 프라이머리가 다운됐습니다. 대응 절차를 알려주세요."
```

리허설 결과 (13:39 실측, `results/raw/demo_20261022_133923.json`)
- 원본: 런북 `high-latency`(응답 지연용) → "커넥션 풀 늘리기, 타임아웃 설정"
- 최종: 런북 `db-down`, `disk-full` → "failover 노드로 전환"
- 지연 6.8초 vs 11.9초, 비용 $0.0028 vs $0.0005

말할 것
> 같은 질문을 원본과 최종에 동시에 넣었습니다. 원본은 응답 지연 매뉴얼을 골라 커넥션 풀을 늘리라고 하고, 최종은 DB 다운 매뉴얼을 골라 예비 DB로 바꿔 타라고 합니다. 비용은 약 6분의 1이고, 대신 몇 초 더 걸립니다.

## 시연 2: 매뉴얼이 없는 질문 (v2 보완 보여 주기, 시간 있으면)

```bash
LANGCHAIN_TRACING_V2=false .venv/bin/python scripts/demo_side_by_side.py --id Q19
```

질문: "외부 PG사 결제 승인 API가 계속 실패합니다. 복구 절차 알려주세요." (등록된 매뉴얼 없음)

리허설 결과
- 원본: 엉뚱하게 `high-latency` 매뉴얼을 골라 커넥션 풀 조치를 안내
- 최종: 런북 **없음** → "등록된 런북 중 해당 절차가 없다"고 말하고 증상을 되묻는다

말할 것
> 맞는 매뉴얼이 없는 질문입니다. 원본은 억지로 아무 매뉴얼이나 골랐고, 최종은 "등록된 절차가 없다"고 말합니다. 이게 v2 보완입니다.

## 다른 질문으로 해 보고 싶을 때

```bash
LANGCHAIN_TRACING_V2=false .venv/bin/python scripts/demo_side_by_side.py --id Q16
```

- `Q16`: 504 타임아웃 + CPU 급증 (매뉴얼 2개가 필요한 복합 질문)
- `Q17`: 메모리 증가 + 응답 지연 (복합 질문)

## 주의

- 결과는 매번 조금씩 다르다 (AI 답이라 문장이 바뀜). 숫자보다 **고른 매뉴얼**을 강조한다.
- 인터넷이나 API가 느리면 15초보다 길어질 수 있다. 30초 넘게 멈추면 `Ctrl+C` 로 끊고, README 3.2의 시연 그림(저장된 실제 실행 기록)을 보여 준다.
- `LANGCHAIN_TRACING_V2=false` 는 LangSmith 월 한도 초과 경고가 화면을 덮지 않게 하는 옵션이다.
- 실행 기록은 `results/raw/demo_<시각>.json` 에 자동 저장된다.
