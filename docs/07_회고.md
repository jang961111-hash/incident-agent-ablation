# 07 회고 (2026-10-22 발표 후)

과제: SKALA 4기 AI Agent Mini-Project 선택과제 1 (베이스 에이전트 개선 + Ablation 검증)
기간: 2026-10-20 세팅 → 10-21 베이스 이식, 실험 → 10-22 13:00 제출, 13:10 발표

## 1. 결과 요약

- 개선 5가지를 원본을 건드리지 않고 설정 스위치로 붙였다: RAG, LLM Judge, 캐스케이드(+캐시), v2 보완, 비동기, 고장 허용.
- 7개 구성 × 60문제 × 3회 = 1,260회 실행. 시험 문제 36개는 v2 구현 전에 커밋으로 고정했다.
- 효과가 확인된 것: RAG(맞는 매뉴얼 누락 -46%p), v2 보완(엉뚱한 매뉴얼 혼입 -24%p). 원본 → 최종 누락 56% → 9%, 혼입 65% → 35%, 장애 1건 비용 -84%.
- 효과가 확인되지 않은 것: 검수자 역할의 Judge(품질 향상 확인 안 됨, +2.7초). 대신 조작 테스트에서 가짜 시스템 이름을 21/29 잡아 코드 검증(0/29)과 서로 보완한다는 것을 확인했다.
- 운영: 동시 질문 10개 62.8초 → 9.2초(5회 반복 6.5~9.4배), 조회 30% 고장 시 0/19 → 18/18(고장 위치 5가지 합계 0/71 → 71/71).
- 로컬 Ollama (발표 후, holdout 36문제 1회): 원본, 개선판 모두 36/36 오류 없이 답함. 개선판은 엉뚱한 매뉴얼 혼입 58% → 3%, 정답 매뉴얼 1위 15/28 → 25/28. 맞는 매뉴얼 누락은 46% → 50%로 줄지 않았다 (dev로 정한 기준값이 holdout에서 엄격).

모든 숫자의 분모, 출처는 `CLAIMS.md`.

## 2. 잘한 것

- **숫자를 손으로 옮기지 않았다.** 결과 JSON → `scripts/claims.py` → `CLAIMS.md`, 문서 숫자는 `scripts/check_claims.py`로 대조했다. 발표 직전까지 README, 대본, 시트 문구를 여러 번 고쳤지만 숫자 불일치 0건을 유지했다.
- **시험 문제를 먼저 고정했다.** holdout을 v2 구현 전에 커밋해 "시험 보고 고쳤다"는 질문에 커밋 시각으로 답할 수 있었다.
- **결론이 바뀌는 재측정을 받아들였다.** 부하 조건을 맞춰 지연을 다시 재자 "캐스케이드가 빠르다"는 결론이 사라졌고, 그대로 보고서에 반영했다.
- **1회 측정을 반복 측정으로 보완했다.** 동시성 5회, 고장 위치 5가지로 다시 재서 방향이 같다는 것을 확인했다.
- **부정적인 결과를 해석으로 바꿨다.** Judge가 품질을 올리지 못한 결과를 숨기지 않고, 조작 테스트로 "어디에 쓸모 있는가"를 찾아 5장의 결론(선생님이 아니라 경비원)으로 만들었다.
- **병렬 작업.** 덱 시안, 대본, 그림 보정, Ollama 조사, 실행을 백그라운드 작업으로 나눠 동시에 진행했다.

## 4. 배운 것

1. **기능을 더하기 전에 재는 법부터 만든다.** 효과가 있을 거라 믿은 Judge는 재 보니 역할이 달랐다.
2. **채점하는 AI도 검증 대상이다.** 평가 Judge는 다른 AI가 떨어뜨린 답 17/29를 합격시켰다. 결론은 코드로 센 지표로 냈다.
3. **측정 조건이 결론을 바꾼다.** 캐시, 부하, 추적 기능처럼 측정 대상이 아닌 것이 숫자를 흔들었다.
4. **모델을 바꾸면 기준도 다시 맞춘다.** OpenAI 임베딩으로 정한 기준값은 로컬 임베딩에서 쓸 수 없었다.
5. **실험용 모델과 배포용 모델은 다를 수 있다.** 실험은 외부 API로 빠르고 공정하게, 배포는 사내망 로컬 모델로 바꿔 끼울 수 있게 설계했다.
