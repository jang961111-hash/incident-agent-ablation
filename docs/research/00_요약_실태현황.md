## 1. 장애는 비싸고, 사회 문제가 됐다

- **비용**: 2024년 설문에서 응답자 54%가 최근 중대 장애 비용이 10만 달러를 넘었다고 답했고, 5명 중 1명은 100만 달러 초과였다. 절차를 지키지 않아 생긴 장애가 전년보다 늘었다 (Uptime Institute, *Annual Outage Analysis 2025*).
- **국내**: 2022 카카오 장애 뒤 정부가 카카오에 "장애 탐지·전파·복구 전 과정 재점검과 자동화 기능 도입 등"을 행정지도했고(강제력 없음), 개정 방송통신발전기본법으로 대형 부가통신사업자·데이터센터에 재난관리 의무가 생겼다. 2023.11 행정전산망 장애 뒤에는 자동관제시스템·디지털안전상황실, 2025-07-08 시행 전자정부법 개정으로 행정 시스템 1~4등급 관리가 들어왔다. 그래도 2025-09-26 국가정보자원관리원 화재로 업무시스템 647개가 멈췄다(초기 집계).
- **시사점(우리 해석)**: Uptime은 비용(54%)과 절차 미준수 증가를 따로 보고했다. 둘을 인과로 묶을 수는 없지만, 장애 대응이 사람이 매뉴얼을 찾아 따르는 일이라는 점에서 "맞는 매뉴얼을 찾아 주는가(누락률)"를 첫 지표로 삼았다.

ChatGPT 교차 조사가 정리한 공통 흐름 5가지(국외 조사와 일치):
1. 검색형 RAG → 로그·메트릭·배포 이력까지 묶은 증거 기반 추론
2. 사람이 묻는 챗봇 → 알림을 받으면 먼저 조사하는 에이전트
3. API별 연동 → MCP 표준 연동
4. 자율 실행 → 승인 게이트를 둔 통제된 실행
5. 정확도 하나 → 오답 위험·비용·지연·불확실성까지 보는 복합 평가

## 3. 그런데 '효과를 어떻게 쟀는지'는 비어 있다

- 공개된 수치는 대부분 업체 주장, PoC, 장애 1건 사례다. 서로 다른 지표(조사 시간, MTTR, 민원 수)라 비교할 수 없다.
  - 예: GS리테일 30분 → 약 2분, Resolve AI 조사 시간 72% 단축 **[업체 주장]**, LG유플러스 AION 품질 불만 모바일 70% 감소 **[업체 주장]**, 현대오토에버 ErrorWatcher "5분"은 모의 데이터 PoC, 삼성계정은 장애 1건 3분 47초.
- 국외 업체 수치도 대부분 "최대 몇 %"이고 측정 방법이 공개되지 않았다(incident.io·Resolve 최대 80%, Datadog 최대 95%, PagerDuty 알림 노이즈 91% 감소 **[업체 주장]**). 널리 인용되는 AWS의 75%·94%는 공식 페이지에서 확인되지 않았다.
- 조사한 범위의 국내 기업·제품 공개 사례에서는 **고정 평가셋이나 Ablation을 공개한 곳을 찾지 못했다** (02_국내_현황 인사이트 5, 자료가 없어 제외한 기업도 많다). 학계에는 통제 실험 연구가 있다(아래 오케스트로·한양대).
- 업계 선두는 내부에서 이미 같은 방식을 쓴다. Datadog은 실제 인시던트 라벨 평가셋과 사람 평가에 맞춘 LLM 판정기를 쓰고, 알림 서비스명을 초기 맥락에 넣는 기능 하나가 일부 조사는 개선했지만 다른 조사는 **나쁘게 만든** 사례를 공개했다(2026-04-07 블로그). 기능 하나를 켜고 끄며 재야 하는 이유, 즉 Ablation의 근거다.
- 국내 연구(오케스트로·한양대, ASPLOS 2026 AIOps 워크숍)는 RCA 에이전트 실패 원인 1위가 데이터 해석 환각(71.2%), 2위가 불충분한 탐색(63.9%)이며 모델과 무관한 구조 문제라고 보고했다.
- **우리 과제의 위치**: 기능 수로 글로벌 제품과 경쟁하지 않는다. 합성 평가셋 60문제와 AI 평가자라는 한계 안에서 **부품별 기여를 Ablation으로 분리해 보였다.** 업계 수치와 직접 비교하지 않는다.

## 4. 연구 근거 — 우리 결과와 맞는가

| 우리 결과 | 같은 방향의 근거 | 주의할 점 |
|---|---|---|
| RAG로 맞는 매뉴얼 누락 56% → 9% | Flow-of-Action(WWW'25 Industry): SOP 기반 멀티에이전트가 ReAct 대비 RCA 정확도 35.5% → 64.0%(SOP만 뺀 비교는 아님). Nissist(ECAI'24): 트러블슈팅 가이드 검색 기반 완화 계획. DPR(EMNLP'20): 의미 검색이 어휘 검색보다 높음 | 우리 원본은 BM25가 아니라 키워드 규칙이라 수치 직접 비교는 안 됨 |
| 파이프라인 안 LLM Judge는 품질 향상 미확인, 지연·비용만 증가 | Huang 외(ICLR'24): 추론 과제에서 외부 피드백 없는 자기교정은 효과가 없거나 해로움(우리 보고서 재작성과 과제는 다름). Kamoi 외(TACL'24): 믿을 만한 외부 신호가 있을 때만 효과. Tyen 외(ACL Findings'24): 병목은 오류 위치를 못 찾는 것 | Self-Refine(NeurIPS'23)은 약 20%p 개선을 보고 → 반대 결과. 피드백 신호가 분명한 과제에서 잰 것이라는 차이 |
| 평가 Judge가 후했다 (독립 평가자 Claude가 불합격으로 본 답의 59%를 합격, 사람 아님) | Thakur 외(GEM² 2025): 판정기 관대함 편향, 퍼센트 일치율은 부족 → kappa를 쓴 근거. Panickssery 외(NeurIPS'24): 자기 출력 선호 | Zheng 외(NeurIPS'23)는 GPT-4 판정기 80% 이상 사람 일치. 우리는 도메인·형식(단일 PASS/FAIL)·평가자 1명이라는 차이 |
| 캐스케이드로 비용 절감 (단독 -73%) | FrugalGPT(TMLR'24) 저가 → 고가 캐스케이드, RouteLLM(ICLR'25) 사전 라우팅. 현업: ServiceNow AIOps LEAP 3.1.2가 Small(GPT-4o mini 등)·Large(GPT-4o 등) 모델 트랙을 고르게 함(캐스케이드인지, 승격 방식은 문서에 없음) | 승급 신호가 관대한 Judge라 절감 일부는 느슨한 검수의 대가일 수 있음(추정) |
| holdout·3회 반복·paired bootstrap·kappa | Koehn(2004), Berg-Kirkpatrick 외(2012) 쌍대 부트스트랩, Dror 외(ACL'18), Miller(2024, 평가 오차 막대), Kapoor & Narayanan(Patterns 2023, 누수) | - |

**환각 대응을 어떻게 해석할까 (우리 해석·가설)**: 국내 연구(보도 기준)는 환각을 실패 원인 1위로 꼽고 구조 개선이 프롬프트 수정보다 낫다고 했다. 우리 실험에서 LLM이 LLM을 검수하는 방식은 품질 향상이 확인되지 않았다. 문헌(Kamoi, Tyen)과 함께 보면 다음 방향은 **코드로 하는 사실 확인(factcheck)이나 도구 재조회 같은 외부 신호**라고 본다. 다만 factcheck 단독 효과는 따로 재지 않았다.

| 우리 노드 | 지금 | 현업 MCP (공식, 2026-10-22 확인) | 권한 |

| route / plan | LLM 분류 | PagerDuty·incident.io·Jira Service Management에서 트리거 알림 원문 | 읽기 |

- 한 줄: **research와 replan_check는 읽기 전용 MCP로 바꿔 끼우면 되고, write에만 쓰기 권한과 사람 승인을 붙인다.**
- 보안: 읽기 전용 기본값, 쓰기는 LangGraph `interrupt`로 승인, 도구 출력(로그·티켓 본문)을 통한 프롬프트 인젝션 차단, 토큰 패스스루 금지, 로컬 서버 버전 고정.
- 함정: 이미 보관(archive)된 저장소(PagerDuty 로컬 서버, `dynatrace-oss/dynatrace-mcp`, `Azure/azure-mcp`)와 유지보수가 끝난 Notion 로컬 서버와 존재하지 않는 주소(`DataDog/datadog-mcp-server` 등)가 검색에 자주 나온다. 04 파일의 확인 목록을 쓴다.

## 6. 정리 — 이 조사가 우리 과제에 주는 것

1. **문제 정의의 근거**: 장애 비용(Uptime), 국내 제도의 자동화 요구 → "맞는 매뉴얼을 찾아 주는가"를 첫 지표로 삼은 배경(인과 근거는 아님).
2. **설계의 근거**: 런북·과거 장애를 근거로 쓰고 MCP로 도구를 붙이는 제품·사례가 많다. 실행을 맡기는 정도는 제품마다 다르고, 우리 에이전트는 조치를 제안만 한다.
3. **차별점**: 공개 사례 대부분이 업체 주장·PoC 수치다 → 우리는 합성 평가셋·AI 평가자 한계 안에서 holdout 고정, 3회 반복, 짝지은 신뢰구간으로 부품별 효과를 분리했다.
4. **반성과 다음 단계**: LLM 자기 검수는 품질 향상이 확인되지 않았다(문헌과 같은 방향) → 코드 기반 사실 확인과 도구 재조회로 검수를 옮기고, 현업 MCP는 읽기 전용부터 붙인다.
