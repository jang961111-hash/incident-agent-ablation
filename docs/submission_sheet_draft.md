# 제출 시트 문구 초안 (병헌 님이 직접 붙여넣기 · 제출)

수치 출처: results/*_latest.json (holdout 36건, 3회 반복), results/stats_holdout.json
마지막 확인: 2026-10-21 최종 (7구성 모두 3회 반복, +비용·final 은 캐시 버그 수정 뒤 cold 3회 재측정). 사람 라벨 kappa 는 라벨 입력 후 추가.

---

## 주요 기능 (짧은 버전, 셀 1칸용)

베이스 에이전트에 RAG·LLM Judge·비용 캐스케이드·v2 보완을 플래그로 붙이고, 하나씩 켜는 7구성 Ablation(60건 중 조정에 안 쓴 holdout 36건, 3회 반복, paired bootstrap 95% CI)으로 기여도를 분리함. 결과: 정답 런북 누락 56%→9%(RAG 효과, 유의), 무관 런북 혼입 65%→35%(v2 보완 효과, 유의), 장애 1건당 비용 -84%. 실제 API로 동시 요청 10건 62.8초→9.2초, 도구 30% 고장 주입 시 고장 맞은 질의 답변 0/19→18/18. LLM Judge는 단독·RAG 위 모두 품질 향상이 확인되지 않았고 지연은 +1.8~2.3초 유의하게 늘었음. 평가 Judge의 관대함은 Judge 무관 지표와 LLM 독립 평가자(Claude) 블라인드 라벨 60건(일치 70%, kappa 0.39, Judge 관대도 59%)으로 확인 [사람 표본 20건 라벨 후 사람-Judge kappa 추가].

## 주요 기능 (긴 버전, 보고서·노션용)

1. 개선 효과 분해 (7구성 Ablation)
   - base / +RAG / +Judge만 / RAG+Judge / +비용 / +v2 보완 / final
   - 평가셋 60건: dev 24건(기준값 조정용) + holdout 36건(v2 구현 전 고정, 최종 보고용)
   - 3회 반복, 구성 간 차이는 질의 단위 paired bootstrap 95% CI로 판정
2. 결과 (holdout)
   - RAG: 정답 런북 누락 -46%p [-70, -22], 런북 어구 포함 +37%p, Judge 통과 +20%p (모두 유의)
   - LLM Judge: 품질 변화 유의하지 않음, 질의당 지연 +2.3초 (유의)
   - v2 보완(최소 유사도·Judge 기준 수정·수치 코드 검증): 무관 런북 혼입 -24%p (유의), 미등록 질의 통과 83%→100%
   - 캐스케이드(1차 gpt-4o-mini, 반려 시만 gpt-4o): 장애 1건당 비용 $0.00343 → $0.00057 (final, base 대비 -84%. 캐스케이드만 켠 +비용 구성은 -73%), 품질 대가 어구 포함 -5%p 비유의
3. 평가자 검증
   - 평가 Judge(gpt-4o)를 파이프라인 Judge(gpt-4o-mini)와 분리
   - Judge 무관 결정적 지표(정답 누락·혼입, 런북 어구 포함)로 결론
   - 독립 평가자(Claude, 블라인드) 60건: 평가 Judge와 종합 일치 70%, kappa 0.39, Judge 관대도 59%
   - 사람 표본 20건 라벨 → 사람-Judge kappa (입력 후 추가)
4. 운영 안정성 (실제 API 벤치)
   - 비동기 I/O: 동시 요청 10건 처리 62.8초 → 9.2초 (약 6.9배)
   - 도구 부분 실패 허용: 모니터링 조회 30% 실패 주입 시 고장 맞은 질의 답변 base 0/19 → final 18/18
   - 최종 구성은 base보다 질의당 +1.4초 (RAG·검수 비용. +비용·final 재측정이 더 가벼운 부하라 지연 차이에는 부하 차이가 섞였을 수 있음)
5. 편향 검증: base는 알림 문구대로 물으면 Recall@1 78%, 자기 말로 물으면 11% / dev→holdout 일반화 격차도 공개
