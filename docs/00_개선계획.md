# 개선 계획

SKALA 4기 AI Agent Mini-Project / 선택과제 1 / G062 장병헌 (광주 2반)

## 문제 설정

베이스 인시던트 대응 에이전트에는 두 가지 구조적 공백이 있다.

1. 런북 선택이 키워드 규칙이다. 표현이 조금만 달라지면 엉뚱한 런북을 집는다.
2. Validator가 규칙 기반이다. 형식은 보지만 내용의 관련성·완전성은 보지 못한다.

둘 다 수업에서 개선 여지로 지목된 지점이다.

## 접근: 개선을 나열하지 않고 기여도를 분해한다

개선 항목을 늘리면 "정확도가 올랐다"까지만 말할 수 있다. 원인이 무엇인지 모른다.
같은 평가셋을 구성별로 돌려 각 개선의 효과를 분리한다.

| 구성 | RAG | Judge | 비용최적화 | 이 구성으로 알 수 있는 것 |
|---|---|---|---|---|
| base | | | | Before 기준선 |
| rag | O | | | RAG 단독 효과 |
| rag_judge | O | O | | Judge가 추가로 올린 양 |
| rag_judge_cost | O | O | O | 비용 절감 시 품질 손실 |

## 측정 축을 두 개로 분리한다

Validator 4지표는 답변 품질이고, Context Precision은 검색 품질로 수업에서 따로 분류된다.
RAG를 넣고 답변 지표만 재면 개선 원인이 검색인지 프롬프트인지 알 수 없다.

- 검색 품질: Recall@1, Recall@3, MRR
- 답변 품질: 관련성, 완전성, 도메인 적합성, 명확성
- 운영: p50/p95 지연, 토큰, 추정 비용, 재작성 횟수

검색은 좋아졌는데 답변이 안 좋아진 구간이 나오면 그것이 한계 분석의 재료가 된다.

## 평가자 자체를 검증한다

Judge는 LLM이므로 틀린다. 평가셋 전건에 본인이 Pass/Fail을 매겨 두고
Judge 판정과의 일치율을 낸다. 일치율이 85%라면 모든 수치를 그만큼의
오차를 안고 읽어야 한다는 사실을 보고서에 명시한다.

## 예상 한계 (실측 후 수정)

- 캐싱은 비용과 지연을 줄이지만 런북 갱신 반영이 늦는다.
- 모델 티어링은 비용을 줄이지만 경량 모델이 맡은 단계에서 품질이 떨어질 수 있다.
- Judge 일치율만큼 모든 측정치에 오차가 있다.
- 평가셋 24건은 통계적으로 작다. 지표 차이가 2~3건 차이로 뒤집힐 수 있다.
