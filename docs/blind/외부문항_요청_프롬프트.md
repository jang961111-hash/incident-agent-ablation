# 외부 문항 요청 프롬프트 (블라인드 시험용)

## 왜 필요한가

기존 평가셋 60문제는 개발자(본인, Claude)가 만들었다. holdout은 개선 전에 고정했지만, 문제를 쓴 사람과 시스템을 만든 사람이 같다.
그래서 **이 저장소의 코드, 질문, 결과를 본 적 없는 다른 AI**에게 문항과 정답 라벨을 받아 **한 번만** 돌리고, 결과를 그대로 공개한다.

## 절차 (규칙)

1. 아래 프롬프트를 ChatGPT 또는 Gemini **새 대화**(파일, 저장소 연결 없음)에 그대로 붙여 넣는다.
2. 받은 YAML을 `eval/external/queries_external_v1.yaml`에 **수정 없이** 저장하고, 실행 전에 커밋한다 (문항, 라벨 고정).
   - 라벨이 이상해 보여도 고치지 않는다. 이견은 별도 파일(`eval/external/label_notes.md`)에만 적는다.
3. `base`와 `final`을 같은 조건으로 돌린다. 기준값, 프롬프트, 코드는 바꾸지 않는다.
4. 결과가 나쁘게 나와도 그대로 README에 싣는다. 재실행으로 좋은 결과를 고르지 않는다.

받은 출처(모델 이름, 날짜)는 YAML 맨 위 주석에 적는다.

---

## 프롬프트 (여기부터 복사)

당신은 온프레미스 서비스를 운영하는 회사의 SRE 팀장입니다. 새로 도입할 "장애 대응 AI 에이전트"를 시험하기 위한 **한국어 당직자 질문 15개**와 정답 라벨을 만들어 주세요. 에이전트가 어떻게 만들어졌는지는 알려 드리지 않습니다. 실제 당직자가 슬랙이나 전화로 물을 법한 말투로 써 주세요.

**회사 시스템 (모니터링에 등록된 6개)**
auth-service(로그인·인증), web-01(웹 서버), payments-service(결제), cache-service(캐시), gateway-service(API 게이트웨이), log-service(로그 수집)

**회사가 가진 장애 대응 매뉴얼 6개 (id: 다루는 장애)**
- cpu-spike: CPU 사용률 급증
- db-down: 데이터베이스 다운·접속 불가
- disk-full: 디스크 용량 부족
- high-latency: 응답 지연(느려짐)
- memory-leak: 메모리 누수(메모리가 계속 늘어남)
- network-timeout: 시스템 간 호출의 네트워크 타임아웃

**만들 질문 15개의 구성**
- 9개: 매뉴얼 6개 중 맞는 것이 분명히 있는 질문. 6개 매뉴얼을 고르게 다루고, 매뉴얼 이름이나 장애 용어를 그대로 쓰지 말고 **증상과 상황을 자기 말로** 묘사한다 (예: "메모리 누수" 대신 "재시작하면 괜찮다가 며칠 지나면 또 죽는다").
- 3개: 위 6개 매뉴얼 중 **맞는 것이 없는** 장애 질문 (예: 인증서 만료, 외부 업체 장애, 권한 문제 등). 그럴듯하게 헷갈리게 쓴다.
- 3개: 증상이 두 가지 이상 겹치거나 정보가 부족해 판단이 어려운 질문. 맞는 매뉴얼이 두 개일 수도 있다.
- 15개 중 4개 이상은 위 6개 시스템이 아닌 다른 시스템 이름을 쓰거나 시스템을 밝히지 않는다.
- 실제 공개된 장애 사례(클라우드·국내 서비스 장애 회고 등)에서 아이디어를 얻어도 좋다. 그 경우 `source`에 사례 이름을 짧게 적는다.

**출력 형식**: 아래 YAML 하나만 출력한다. 설명 문장은 YAML 밖에 쓰지 않는다.

```yaml
queries:
  - id: X01
    category: normal        # normal | no_runbook | ambiguous
    query: "질문 원문"
    gold_runbooks: [memory-leak]   # 맞는 매뉴얼 id 목록. 맞는 것이 없으면 []
    rationale: "왜 이 매뉴얼이 정답인지 한 문장"
    source: ""              # 참고한 공개 사례가 있으면 이름, 없으면 빈 문자열
  # ... X15 까지
```
